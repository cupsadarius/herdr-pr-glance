# Glance PR — implementation plan

Status: **Proposed; awaiting document review. Do not start implementation yet.**

**Goal:** Build a distributable Herdr plugin showing the current branch's PR, CI,
statistics, and on-demand cached discussions, using gh for GitHub access.

**Architecture:** A Go executable uses Bubble Tea's model/update/view loop. Herdr
context, GitHub retrieval, and disk caching are independent packages. Asynchronous
commands return messages tagged with source generations; only Update mutates UI
state. A versioned install hook selects and verifies prebuilt release binaries.

**Tech stack:** Go, Bubble Tea v2, GoReleaser, git, gh, Herdr 0.8.2+.

**Spec:** [Design specification](../specs/2026-09-08-glance-pr-design.md).

## Global constraints

- Work in the supplied directory, currently containing documentation only.
- Origin: `git@github.com-personal:cupsadarius/herdr-pr-glance.git`. Public release
  and installation identifiers use `cupsadarius/herdr-pr-glance`, not the SSH alias.
- macOS/Linux, amd64/arm64. Users install prebuilt binaries without a Go toolchain.
- Build release binaries with `CGO_ENABLED=0`; pin dependencies in `go.mod`/`go.sum`.
- Use `HERDR_BIN_PATH` and working-pane context, never the plugin's own cwd.
- Local checks: 2 seconds. Visible summary polling: 60 seconds.
- Discussions are fetched only on section opening or explicit refresh.
- Cache freshness: 300 seconds. Cleanup age: 7 days.
- Preserve same-PR stale data on failure; discard obsolete source results.
- GitHub operations are reads. External commands receive argument arrays.
- Do not edit user keybindings, push commits, publish releases or create credentials.
- Preparing and locally testing release automation is within implementation scope;
  actually publishing artifacts is a separate step requiring user instruction.

## File and interface map

Module path: `github.com/cupsadarius/herdr-pr-glance`.

| Location | Responsibility |
| --- | --- |
| `cmd/herdr-pr-glance/main.go` | Open, overlay, view, snapshot and version commands |
| `internal/model/` | Shared source, PR, discussion and cache records |
| `internal/command/` | Context-bound subprocess execution and typed errors |
| `internal/herdr/` | Context, source selection, visibility, pane launch and zoom |
| `internal/github/` | gh discovery, normalization, GraphQL pagination |
| `internal/cache/` | Atomic discussion persistence and cleanup |
| `internal/ui/` | Bubble Tea model, messages, commands, rendering and controls |
| Package-local `*_test.go` and `testdata/` | Behavioral tests and synthetic fixtures |
| `herdr-plugin.toml`, `VERSION` | Plugin entrypoints and matching artifact version |
| `scripts/install.sh` | Platform selection, download, checksum and binary replacement |
| `.goreleaser.yaml`, `.github/workflows/` | CI and versioned release artifacts |

Keep interfaces at their consumers. Proposed service contracts are:

```go
type Runner interface {
    Run(ctx context.Context, cwd string, argv ...string) (string, error)
}
type SourceResolver interface {
    Resolve(ctx context.Context) (model.Source, error)
}
type GitHub interface {
    Snapshot(ctx context.Context, source model.Source) (model.Snapshot, error)
    Discussion(ctx context.Context, pr model.PR, section model.Section) (model.Discussion, error)
}
type Cache interface {
    Get(pr model.PR, section model.Section, now time.Time) (model.CacheEntry, bool, error)
    Put(pr model.PR, section model.Section, data model.Discussion, now time.Time) error
}
```

These are design signatures, not an additional implementation to scaffold now.
`Source` includes pane/workspace/tab IDs, checkout root, branch, HEAD and visibility.
`PR` is canonical host/repository/number/node identity. `Snapshot` contains optional
PR identity, a valid absence reason, summary statistics, checks and fetch time.
`Discussion` is a complete section payload. `CacheEntry` adds fetch time. An absent
working source and other invalid local states use explicit typed reasons; valid
“No PR” is distinct from authentication/network failure.

The UI owns the state transition boundary through Bubble Tea's `Init`, `Update`,
and `View`; do not add a second independently mutable controller. Result messages
include generation and section. Inject time and service interfaces in tests.

## Task 2: Exact PR and CI snapshots

**Files:** `internal/github/snapshot.go`, `internal/github/client.go`,
`internal/model/types.go`, colocated tests and `testdata/`.

**Consumes:** `Source`, `Runner`. **Produces:** `Snapshot` with no discussion bodies.

- [ ] Write failing command-boundary fixtures for open, draft, merged/closed,
  no associated PR, failed authentication and network failure. Confirm gh's actual
  exit/output contract before distinguishing absence from errors.
- [ ] Test mixed check states: success, failure, timed out, cancelled, action
  required, pending, neutral, skipped, unknown and legacy status contexts. Assert
  visible counts and ordering, not raw fixture equality.
- [ ] Include multiple check pages and a PR with 143 commits but only 100 commit
  records in a hypothetical first page: displayed commit count must remain 143.
- [ ] Discover the associated PR with `gh pr view --json …` in the source checkout.
  Derive host/repository/node identity from the returned PR. Preserve gh's remote,
  fork and host behavior instead of assuming `origin` or public github.com.
- [ ] Use narrow GraphQL queries for exact totals and paginated checks as needed.
  Reject GraphQL errors even when partial `data` is present. Command cancellation
  must stop obsolete work rather than merely stop displaying it.
- [ ] Test same-number PRs across hosts/repositories. At the external command
  boundary, assert automatic queries do not request discussion bodies.
- [ ] Run `go test ./internal/github/...`.

## Task 3: Complete discussions and cache

- [ ] Test a later-page failure: no claim of completeness, and no replacement of
  an older complete cache by partial data.
- [ ] Implement independent connection cursors, including nested replies. Preserve
  stable ID, author, timestamp, body, location, status and browser URL.
- [ ] Test canonical keys across hosts/repositories/sections, corrupt JSON, schema
  mismatch, atomic replacement, private permissions, cleanup and write errors.
- [ ] Implement versioned JSON beneath Herdr's state directory using hashed names,
  mode 0700 directories and 0600 files. Use same-directory temporary files and
  rename after a successful write; remove abandoned temporary files on failure.
- [ ] Cache only complete results. Write failure preserves fetched data in memory
  and surfaces a warning; read failure allows a fresh on-demand request.
- [ ] Inject time: fetched at Unix time 1000 is fresh at 1299, stale at 1300, and
  remains readable when stale. Test cleanup after seven days without sleeping.
- [ ] Run `go test ./internal/github/... ./internal/cache/...`.

## Task 4: Bubble Tea state and refresh policy

**Files:** `internal/ui/model.go`, `internal/ui/update.go`,
`internal/ui/commands.go`, colocated behavior tests.

**Consumes:** source, GitHub and cache services. **Produces:** state transitions
and asynchronous commands, with a single UI state owner.

- [ ] Use a fake clock and controllable command completion. Write failing tests
  for initial summary, 60-second refresh, hidden-tab suspension, branch changes,
  in-flight coalescing and a previous generation completing after a source change.
- [ ] Cover every row in the spec's cache behavior table. A key test opens Reviews
  at time 1000, completes a fetch, then advances to 1400 while staying in Reviews:
  the view is stale but the discussion request count is still exactly one.
- [ ] Verify that Overview ticks never request discussion and that opening a fresh
  disk cache makes no discussion request. Observe the external boundary and visible
  model state; avoid tests that assert only a mock was called.
- [ ] Implement asynchronous Bubble Tea commands that return typed results. Only
  Update changes state. Carry source generation and section through each result;
  cancel obsolete contexts and still reject late results after cancellation races.
- [ ] Implement active-section `r`, cache-freshness bypass, known rate-limit
  cooldown and summary failure backoff capped at five minutes. Keep same-PR stale
  data on failure. Manual refresh respects known rate-limit cooldowns.
- [ ] Verify summary completion never causes a discussion query, including while
  Reviews is selected, and incomplete pagination never marks discussion fresh.
- [ ] Run `go test ./internal/ui/...` and `go test -race ./internal/ui/...` on a
  supported native host with the toolchain required for Go race instrumentation.

## Task 6: Versioned binary installation and release automation

**Files:** `VERSION`, `scripts/install.sh`, `.goreleaser.yaml`,
`.github/workflows/ci.yml`, `.github/workflows/release.yml`,
`internal/installtest/install_test.go`, manifest build hook.

**Deliverable:** Reproducible artifacts and a tested installer; no release published.

- [ ] Use initial version `0.1.0` consistently in VERSION and manifest. Release tags
  are `v0.1.0` style. Enforce manifest/VERSION/tag agreement in release validation.
- [ ] Configure GoReleaser with `CGO_ENABLED=0`, darwin/linux, amd64/arm64. Archive
  names are `herdr-pr-glance_VERSION_OS_ARCH.tar.gz`; put the single executable
  `herdr-pr-glance` at archive root and publish a `checksums.txt` file.
- [ ] Add a manifest build hook with argv `["sh", "scripts/install.sh"]`. It reads
  VERSION relative to the plugin root, maps `uname` to the four supported targets,
  and uses `gh release download` for that exact tag/repository/archive/checksums.
- [ ] Test the shell installer from Go using temporary fixtures and fake external
  commands on PATH, asserting installed executable contents and failure behavior.
  Cover all target mappings, paths with spaces, unsupported platform, missing asset,
  failed download, checksum mismatch, valid install and preservation of an old binary.
- [ ] Implement bounded downloads, portable SHA-256 verification using `sha256sum`
  or `shasum -a 256`, extraction of only the expected archive member, executable
  permissions and atomic replacement in `bin/`. Cleanup temporary files on error.
  Never edit the manifest, silently use latest, or download when a pane opens.
- [ ] CI runs tests, formatting and vet on native macOS/Linux; race tests run only
  on supported native targets. Release cross-builds use cgo disabled, independently
  of race instrumentation requirements. Pin automation actions/tool versions.
- [ ] Prepare tag-triggered release automation with publication permissions limited
  to the release job. It must validate the version and require green checks for
  the tagged commit. Do not trigger or publish as part of implementation.
- [ ] Run `goreleaser check` and `goreleaser release --snapshot --clean`; verify all
  four archives and checksums and run native `version`/snapshot smoke tests.
- [ ] Document release ordering: upload matching assets successfully before advancing
  the default branch's install manifest to that version. A pinned repository tag
  always installs its exact matching artifact, with no implicit upgrade.
